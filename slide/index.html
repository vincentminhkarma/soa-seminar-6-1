SOA — Service-Oriented Architecture — tổ chức năng lực của hệ thống thành các dịch vụ có giao diện rõ ràng.

Hình dung một quầy tiếp nhận: bạn đưa phiếu yêu cầu, nhận kết quả, không cần biết quy trình bên trong quầy.

S

Service · Một năng lực rõ ràng

AI Booking Service nhận văn bản và trả thông tin đặt phòng. Nó không kiêm luôn thanh toán hay quản lý khách sạn.

C

Contract · Một cách giao tiếp chung

Client biết gửi trường nào, nhận cấu trúc gì và lỗi có nghĩa gì. Trong demo: HTTP REST và JSON.

L

Loose coupling · Ít phụ thuộc nội bộ

Client không import parser hay giữ API key AI. Có thể đổi cách trích xuất, miễn giữ hợp đồng đã cam kết.

R

Reuse · Nhiều nơi cùng sử dụng

Một service có thể phục vụ nhiều consumer. Không cần chép logic AI vào từng ứng dụng.

SOA ≠ Microservices

Cả hai đều phân tách theo dịch vụ. Microservices thường nhấn mạnh dịch vụ nhỏ, triển khai độc lập và quyền sở hữu dữ liệu; SOA rộng hơn. Demo này minh họa nguyên lý hướng dịch vụ, không phải một hệ thống microservices production hoàn chỉnh.

Phản hồi · Ví dụ cấu trúc

{
  "mode": "regex",
  "booking": {
    "room_type": "STANDARD",
    "check_in": "2026-10-20",
    "check_out": "2026-10-22"
  },
  "status": "EXTRACTED",
  "availability": null,
  "tool_trace": [],
  "reply": null,
  "total_tokens": 0,
  "elapsed_ms": 0.12
}

elapsed_ms chỉ minh họa cấu trúc, không phải số đo benchmark.

200 không có nghĩa “đã đặt phòng”.

EXTRACTED chỉ nói đã đủ ba trường. NEED_MORE_INFO nghĩa là còn thiếu, trường tương ứng là null. Service không tạo booking.

Lỗi cũng là một phần hợp đồng.

422: đầu vào sai. 503: chưa cấu hình gateway/model. 502: upstream hoặc phản hồi AI lỗi. 403: gọi AI qua tunnel bị chặn. Không âm thầm đổi AI sang regex.

Dữ liệu chuẩn chưa chắc dữ liệu đúng.

Schema kiểm tra hình dạng, enum và ngày. Không chứng minh AI hiểu đúng ý khách. Cần đối chiếu dữ liệu gốc và có người xác nhận trước nghiệp vụ quan trọng.

Hợp đồng là một class.

FastAPI đọc class này để kiểm tra request và sinh Swagger. Gửi sai hình dạng nhận 422 trước khi chạm tới logic.

class Input(BaseModel):
    raw_text: str = Field(min_length=1, max_length=2000)
    mode: Literal['regex', 'openai', 'tools'] = 'regex'

class Booking(BaseModel):
    room_type: Literal['STANDARD', 'DELUXE', 'SUITE'] | None = None
    check_in: date | None = None
    check_out: date | None = None

Endpoint là cửa tiếp nhận.

Consumer chỉ biết URL và JSON. Đổi regex sang AI bên trong không bắt consumer sửa code.

Cách 1 · Regex.

Miễn phí, nhanh, nhưng chỉ hiểu tên phòng chuẩn và ngày đủ năm. Viết “phòng tiêu chuẩn” là trượt.

room = re.search(r'\b(STANDARD|DELUXE|SUITE)\b', text, re.I)
dates = re.findall(
    r'\b(?:\d{4}-\d{2}-\d{2}|\d{1,2}/\d{1,2}/\d{4})\b', text)

Cách 2, 3 · AI và Tool Calling.

AI chỉ đề xuất tên hàm và tham số. Backend kiểm tra, so khớp với booking đã xác thực, rồi mới chạy hàm tồn kho.

# Lượt 1: AI trích xuất JSON, Pydantic kiểm tra
result = await call(messages, response_format={'type': 'json_object'})
booking = Booking.model_validate_json(result['choices'][0]['message']['content'])
# Lượt 2: AI đề xuất tool, backend so khớp rồi mới chạy
result = await call(messages, tools=[TOOL], tool_choice=...)
arguments = Booking.model_validate_json(tool_call['function']['arguments'])
if arguments != booking: raise ValueError(...)
availability = check_room_availability(**arguments.model_dump(mode='json'))
# Lượt 3: gửi kết quả tool, AI viết câu trả lời
final = await call(messages)

Cài đặt ngay
trên máy của bạn.

Khoảng 15 phút, không cần API key, không tốn phí. Mỗi bước có kết quả mẫu để tự đối chiếu trước khi sang bước sau.

  1. Kiểm tra công cụ 2 phút

    Cần Python 3.11 trở lên và Git. Chưa có thì cài từ python.org và git-scm.com. Khi cài Python nhớ tích Add python.exe to PATH, cài xong mở PowerShell mới.

    python3 --version
git --version
    py --version
git --version

    Thấy Python 3.11 trở lên (3.12, 3.13… đều được) và một phiên bản Git.

  2. Tải mã nguồn 2 phút

    Clone repo của nhóm rồi đi vào thư mục vừa tải. Mọi lệnh sau đều chạy từ thư mục này.

    git clone https://github.com/vincentminhkarma/soa-seminar-6-1.git
cd soa-seminar-6-1

    Không dùng Git: trên trang GitHub bấm Code → Download ZIP, giải nén, rồi mở terminal tại thư mục vừa giải nén (thư mục có requirements.txt).

    Lệnh lsdir liệt kê được service, client, slide và requirements.txt.

  3. Tạo môi trường ảo, cài thư viện 3–5 phút

    Môi trường ảo .venv giữ thư viện riêng cho bài này, không đụng tới Python của máy. Windows gọi thẳng Python trong .venv nên không cần Activate, không vướng Execution Policy.

    python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
    py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

    Thấy dòng Successfully installed kèm fastapi, uvicorn, pydantic; đầu dòng lệnh hiện (.venv).

  4. Chạy service 1 phút

    python service/soa_service.py
    .\.venv\Scripts\python.exe service\soa_service.py

    Terminal in Uvicorn running on http://127.0.0.1:8000. Giữ nguyên terminal này, tắt nó là service dừng.

Gặp lỗi khi cài?

python3 / py không được nhận ra

Python chưa cài hoặc chưa có trong PATH. Cài lại từ python.org (Windows tích Add python.exe to PATH), đóng terminal và mở terminal mới.

macOS báo “xcrun: error: invalid active developer path” khi gõ git

Chạy xcode-select --install, chờ cài xong rồi gõ lại lệnh git.

Could not open requirements file

Đang đứng sai thư mục. cd vào soa-seminar-6-1, nơi có file requirements.txt.

No module named uvicorn / fastapi

Đang dùng Python ngoài môi trường ảo. macOS/Linux chạy source .venv/bin/activate; Windows gọi .\.venv\Scripts\python.exe như các lệnh trên.

Address already in use: cổng 8000 đang bận

Đổi PORT = 8001 trong service/config.py rồi chạy lại, mở http://127.0.0.1:8001/docs, chạy thực nghiệm kèm --base http://127.0.0.1:8001, ngrok dùng ngrok http 8001.

    Mở http://127.0.0.1:8000/docs → POST /api/v1/extract-booking → Try it out → dán nội dung dưới vào ô Request body → Execute.

    {"raw_text": "Standard từ 20/10/2026 đến 22/10/2026", "mode": "regex"}

    Code 200, "status": "EXTRACTED", "check_in": "2026-10-20".

    Sửa body rồi Execute lại. Đoán kết quả trước khi bấm:

    Thay đổi Kết quả theo hợp đồng

    "mode": "magic" 422 · mode ngoài regex, openai, tools
    "mode": "openai" 503 · chưa cấu hình gateway AI

  2. Chạy kiểm thử và thực nghiệm 2 phút

    Mở terminal thứ hai, cd vào lại thư mục soa-seminar-6-1 rồi kích hoạt .venv.

    source .venv/bin/activate
python -m unittest discover -s service -v

    Ran 10 tests … OK. Thực nghiệm in "correct": 6 trên "count": 8: regex trượt câu “Phòng tiêu chuẩn…” và câu đảo thứ tự ngày. Đúng thiết kế, đây là chỗ AI phát huy.

  3. Tự viết một consumer 5 phút

    Ý chính của SOA: gọi được service mà không import một dòng Python nào của nó.

    Trình duyệt, không cài gì. Trên trang /docs nhấn F12 → Console, dán đoạn sau rồi Enter. Chrome có thể yêu cầu gõ allow pasting trước.

    const r = await fetch('/api/v1/extract-booking', {
  method: 'POST',
  headers: {'Content-Type': 'application/json'},
  body: JSON.stringify({raw_text: 'Suite từ 25/10/2026 đến 27/10/2026', mode: 'regex'})
});
console.log(r.status, await r.json());

    Hoặc từ terminal.

    curl -X POST http://127.0.0.1:8000/api/v1/extract-booking -H 'Content-Type: application/json' -d '{"raw_text":"Suite từ 25/10/2026 đến 27/10/2026","mode":"regex"}'
    Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8000/api/v1/extract-booking -ContentType 'application/json' -Body '{"raw_text":"Suite 2026-10-25 den 2026-10-27","mode":"regex"}'

    Nhận SUITE, 2026-10-25, 2026-10-27, status EXTRACTED. Bài tập: thay raw_text bằng câu của bạn, đoán status trước khi gửi.

  4. Cho máy khác gọi qua ngrok tùy chọn · 5 phút

    Cần tài khoản ngrok miễn phí và ngrok CLI (ngrok.com/download, hoặc brew install ngrok). Authtoken lấy trong dashboard ngrok, không phải API key AI. Giữ terminal service chạy, mở terminal mới: 

    ngrok config add-authtoken <AUTHTOKEN_CUA_BAN>
ngrok http 8000

    Chép địa chỉ https://… ở dòng Forwarding, mở địa chỉ đó thêm /docs trên điện thoại dùng 4G, gửi request mode: regex: cùng JSON như trên máy. Gửi mode: openai qua tunnel nhận 403, cố ý để bảo vệ key.

  5. Thử AI thật tùy chọn · cần API key

    Cách 1, trên giao diện. Mở http://127.0.0.1:8000 trên chính máy chạy service → nhập Base URL gateway và key → Kiểm tra & tải models → chọn model → Sử dụng model. Sau đó gửi lại bước 05 với "mode": "openai" hoặc "tools".

    Cách 2, file .env ở thư mục gốc, để không phải gõ key trên màn hình. Lệnh dưới tạo file (không ghi đè file đã có) rồi mở ra để điền ba biến GATEWAY_BASE_URL, GATEWAY_API_KEY, GATEWAY_MODEL:

    [ -f .env ] || printf '# Cau hinh gateway AI\nGATEWAY_BASE_URL=\nGATEWAY_API_KEY=\nGATEWAY_MODEL=\n' > .env; open -e .env
    if (!(Test-Path .env)) { Set-Content .env "# Cau hinh gateway AI`nGATEWAY_BASE_URL=`nGATEWAY_API_KEY=`nGATEWAY_MODEL=" }; notepad .env

    Điền sau dấu =, không dấu cách, không dấu nháy, ví dụ GATEWAY_BASE_URL=https://api.openai.com/v1. Lưu file, rồi khởi động lại service (Ctrl+C, chạy lại lệnh bước 04).

    Mode tools với “Deluxe từ 22/10/2026 đến 23/10/2026” trả "available": true và có tool_trace; đổi thành 20 đến 21 thì hết phòng.

    Có phí theo token, chỉ chạy khi chủ key đồng ý. Key nhập trên giao diện chỉ giữ trong RAM; file .env nằm trong .gitignore nên không lên GitHub. Không có key vẫn hoàn thành đủ bước 01–07.

Bảo vệ key và dữ liệu đầu vào.

Demo giữ cấu hình gateway trong RAM, không trả key về client; cấu hình và AI chỉ dùng local. Không gửi dữ liệu khách thật tới gateway không tin cậy. Prompt không phải hàng rào bảo mật tuyệt đối.

Phân biệt demo với production.

Hiện chưa có auth, rate limit, retry, persistence hay kiểm soát đặt phòng đồng thời. Tồn kho cố định tháng 10/2026, tra cứu tối đa 30 đêm. Đây là giới hạn thật, không phải tính năng đã hoàn thiện.

Đo trước khi kết luận.

So sánh trên cùng bộ mẫu, công bố cả mẫu sai, ghi model và ngày chạy. Token không tự bằng tiền; chế độ tools nhiều lượt gọi nên không so tốc độ như một lượt extraction.

Khi chia sẻ qua ngrok: dùng regex. Tunnel chỉ chuyển tiếp HTTP, không tự thêm xác thực và không biến laptop thành hosting lâu dài.

API và service khác nhau thế nào?

Service là năng lực xử lý cùng phần triển khai của nó. API là giao diện để bên khác sử dụng năng lực ấy. Ví dụ: AI Booking Service là “quầy xử lý”; POST /api/v1/extract-booking là “cửa tiếp nhận”.

Vì sao đây là một bài học SOA, không chỉ là gọi AI?

Điểm chính là tách trách nhiệm, định nghĩa hợp đồng và để các consumer giao tiếp qua giao diện chung. OpenAI chỉ là một dependency của service. Đổi nhà cung cấp AI không nhất thiết phải đổi consumer nếu giữ hợp đồng và ý nghĩa dữ liệu.

Có bắt buộc dùng FastAPI thay vì Spring Boot?

Không. Spring Boot có thể gọi AI trực tiếp. Adapter riêng phù hợp khi cần chia sẻ logic AI cho nhiều consumer, tách vòng đời triển khai hoặc tận dụng hệ sinh thái Python; đánh đổi là thêm một lần gọi mạng và vận hành thêm service.

AI có tự chạy hàm hay truy cập database không?

Không. Model trả đề xuất tên hàm và arguments. Backend quyết định có chấp nhận không rồi mới thực thi. Trong demo, hàm tồn kho nằm ngay trong FastAPI và đọc dữ liệu giả lập, không truy cập database.

JSON mode có phải Function Calling không?

Không. JSON mode yêu cầu đầu ra JSON; Tool Calling tạo đề xuất gọi hàm với tham số. JSON hợp lệ cũng không đồng nghĩa tuân thủ schema nghiêm ngặt hoặc nội dung chính xác. Backend vẫn cần xác thực.

AI nói còn phòng thì có thể xác nhận ngay?

Không. Phải kiểm tra kết quả nghiệp vụ từ backend. Ngay cả tra cứu còn phòng cũng chưa giữ được phòng: hệ thống thật cần thao tác đặt/giữ chỗ có kiểm soát đồng thời. Demo không thực hiện bước đó.

Không có API key thì học được gì?

Chạy regex để hiểu request/response, thử dữ liệu thiếu và dữ liệu sai, dùng Swagger hoặc viết một HTTP client. Regex là đối chứng có giới hạn, không phải AI miễn phí. Chỉ thử AI thật khi có cấu hình và quyền sử dụng key.

Nếu AI chậm hoặc lỗi thì SOA giải quyết hết không?

Không tự động. Ranh giới dịch vụ giúp cô lập trách nhiệm, nhưng vẫn phải thiết kế timeout, kiểm soát tải và chiến lược lỗi. Hàng đợi phù hợp khi nghiệp vụ chấp nhận xử lý bất đồng bộ; không cần thêm chỉ để sơ đồ trông phức tạp.
